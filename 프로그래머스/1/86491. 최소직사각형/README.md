## 문제 요약
명함들을 자유롭게 **회전**시켜 모두 담을 수 있는 가장 작은 지갑의 넓이를 구한다.

## 접근 방법
- 명함은 눕혀도 되므로, 먼저 모든 명함을 **긴 변이 가로로 오도록 통일**한다.
  (`sizes[idx][0] < sizes[idx][1]`이면 두 값을 교환) 이 한 줄로 "어떤 명함을 돌릴까"라는
  조합 문제가 통째로 사라진다.
- 통일하고 나면 답은 **긴 변들의 최댓값 × 짧은 변들의 최댓값**이다.
  모든 명함을 같은 방향으로 눕힌 배치가 항상 최적이라, 회전 조합을 따로 탐색할 필요가 없다.
- 정렬(O(N log N))도 필요 없다. 최댓값 두 개만 있으면 되므로 한 번의 순회로 끝난다.

### 다시 볼 때 고칠 점
- 리스트 컴프리헨션을 두 번 만들어 각각 `max`를 취하는데, 교환 루프에서 `max_width`,
  `max_height`를 함께 갱신하면 순회 3번 → 1번, 임시 리스트 2개 → 0개가 된다.
- 값 교환은 `sizes[idx][0], sizes[idx][1] = sizes[idx][1], sizes[idx][0]` 대신
  `long, short = max(w, h), min(w, h)` 처럼 원본을 건드리지 않는 편이 안전하다.
  (프로그래머스는 인자를 재사용하지 않지만, 매개변수를 직접 수정하는 습관은 위험하다.)

## 복잡도
- 시간: O(N) — 명함 수만큼 한 번씩 훑는다.
- 공간: O(N) — 컴프리헨션이 만드는 임시 리스트. 위 개선을 적용하면 O(1).
