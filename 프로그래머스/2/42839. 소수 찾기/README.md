## 문제 요약
흩어진 숫자 조각을 이어 붙여 만들 수 있는 **서로 다른 소수의 개수**를 구한다.

## 접근 방법
- 조각을 몇 개 쓸지(`i = 1 ~ len`) 정하고, 그 개수만큼의 **순열**(`permutations`)을 전부 만든다.
  조합이 아니라 순열인 이유는 `[1, 7]`에서 `17`과 `71`이 서로 다른 수이기 때문이다.
- 순열 결과를 `set`으로 감싸, **같은 숫자 조각이 중복될 때**(`"011"`의 두 `1`) 생기는
  똑같은 튜플을 걷어낸다.
- `int("".join(arr))`로 바꾸는 것이 앞자리 0 처리까지 겸한다. `"011"` → `11`이 되어
  "11과 011은 같은 수"라는 조건이 자동으로 지켜진다.

### 다시 볼 때 고칠 점 (실행시간 8,869 ms의 원인)
- `isPrime`이 `1 ~ value`를 전부 나눠보며 약수 개수를 센다. 7자리면 한 번 판정에
  최대 987만 번 나눗셈이다. **`2 ~ √value`만 확인**하면 O(√V)로 떨어지고,
  만들 수 있는 최댓값까지 **에라토스테네스의 체**를 한 번 돌려두면 판정이 O(1)이 된다.
- `answer`가 리스트라 `num not in answer`가 매번 **선형 탐색**(O(K))이다.
  `set`으로 바꾸면 O(1)이고, 마지막에 `len(answer)`는 그대로 쓸 수 있다.
- `if count == 2: return True / else: return False`는 `return count == 2` 한 줄이면 된다.

## 복잡도
- 시간: O(Σᵢ P(L,i) · V) — 순열 개수(L ≤ 7이라 최대 13,700여 개)마다 O(V) 소수 판정이 붙는다.
  판정을 √V로 바꾸면 O(Σᵢ P(L,i) · √V)로 체감이 확 달라진다.
- 공간: O(Σᵢ P(L,i)) — 순열을 담는 집합과 찾은 소수 목록.
