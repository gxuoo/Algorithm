## 문제 요약
던전마다 **최소 필요 피로도**와 **소모 피로도**가 있을 때, 피로도 `k`로 돌 수 있는
**최대 던전 수**를 구한다.

## 접근 방법
- 던전이 최대 8개라 방문 순서를 전부 시도해도 8! = 40,320가지다. `visited` 배열을 쓴
  **DFS + 백트래킹 완전탐색**으로 충분하다.
- 핵심은 `dfs(k)`의 반환값을 "**지금 피로도 k에서 앞으로 더 돌 수 있는 최대 던전 수**"로
  정의한 것이다. 그래서 `best = max(best, 1 + dfs(k - 소모))` 한 줄로 최댓값이 접히고,
  전역 답 변수나 `depth` 인자를 따로 들고 다닐 필요가 없다.
- 더 들어갈 던전이 없으면 루프가 한 번도 안 돌고 `best = 0`이 반환되면서 재귀가 끝난다.
  별도의 종료 조건 분기를 쓰지 않아도 되는 구조다.
- 진입 가능 여부는 `visited[i] or k < dungeons[i][0]` 한 줄로 거른다. **최소 필요 피로도**로
  들어갈 수 있는지 보고, 나올 때 **소모 피로도**만 깎는다는 점을 헷갈리지 않아야 한다.
- 중첩 함수라 `dungeons`, `visited`를 클로저로 그대로 참조한다. 인자로 넘기는 것보다 간결하다.

### 다시 볼 때 고칠 점
- 파일 맨 아래 `print(solution(80, [[80,20],[50,40],[30,10]]))` 테스트 호출이 남아 있다.
  채점에는 지장이 없지만 제출 전에 지우는 편이 깔끔하다.

## 복잡도
- 시간: O(D!) — 던전 D개의 방문 순서 전부. D ≤ 8이라 40,320가지로 여유롭다.
- 공간: O(D) — `visited` 배열과 최대 D 깊이의 재귀 스택.

## 알고리즘 유형
완전탐색, DFS, 백트래킹
