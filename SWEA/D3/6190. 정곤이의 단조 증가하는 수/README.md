## 문제 요약
N개의 수 중 **서로 다른 두 수를 곱해** 만들 수 있는 값들 가운데,
각 자리 숫자가 왼쪽에서 오른쪽으로 감소하지 않는(단조 증가하는) 수의 **최댓값**을 구한다.
그런 수가 하나도 없으면 -1을 출력한다.

## 접근 방법
- 두 수의 곱은 곱셈 순서를 바꿔도 같으므로, `i < j` 인 쌍만 보면 모든 조합을 중복 없이 훑는다.
  → 바깥 루프 `i = 0 ~ n-2`, 안쪽 루프 `j = i+1 ~ n-1`.
- 단조 증가 판정(`is_mono`)은 곱을 **문자열로 바꿔 인접한 두 자리만 비교**한다.
  숫자 문자 `'0'~'9'`는 아스키 순서가 크기 순서와 같으므로 `s[i] > s[i + 1]` 로 바로 비교할 수 있고,
  한 곳이라도 앞자리가 더 크면 즉시 `False`를 반환한다.
- 최댓값 갱신 조건을 `m > result and is_mono(m)` 순으로 둔 것이 포인트다.
  파이썬 `and`는 **단축 평가**라서, 지금 최댓값보다 작은 곱은 문자열 변환·자리 비교를
  아예 하지 않고 넘어간다. 비싼 검사를 싼 검사 뒤로 미룬 것.
- `result`를 -1로 시작해 두면 "단조 증가하는 수가 없음"과 "정답 출력"을 따로 처리할 필요가 없다.

## 복잡도
- 시간: O(N² · log M) — 쌍의 개수가 N²/2이고, 각 곱 `M`의 자릿수가 log M.
  단축 평가 덕분에 실제 판정 호출 수는 이보다 훨씬 적다.
- 공간: O(N) — 입력 배열. 판정에 쓰는 문자열은 자릿수 길이뿐이다.
