## 문제 요약
숫자가 적힌 벽돌이 쌓인 W×H 격자에 구슬을 N번 떨어뜨린다. 맞은 벽돌은 자기 숫자만큼의
십자 범위를 **연쇄 폭발**시키고, 남은 벽돌은 아래로 내려온다. 구슬을 다 썼을 때 남는
벽돌 수의 **최솟값**을 구한다.

## 접근 방법
- 제약이 N ≤ 4, W ≤ 12라 쏠 열의 조합은 최대 12⁴ = 20,736가지뿐이다. 가지치기 없이
  `search`가 매 단계 W개 열을 전부 시도하는 **완전탐색**으로 충분하다.
  분기마다 `[row[:] for row in board]`로 사본을 떠서 형제 가지에 영향이 가지 않게 했다.
- `explode`는 구슬이 맞히는 지점(그 열에서 위에서부터 처음 만나는 벽돌)을 시작점으로
  **BFS 연쇄 폭발**을 돌린다. 벽돌 숫자 `k`는 상하좌우로 각각 `k-1`칸까지 퍼지는 범위다.
  - 중간이 빈칸이어도 `continue`로 **통과해서 계속 뻗어나가고**, 격자를 벗어나면
    그 방향은 `break`로 끊는다. 이 둘을 구분하는 게 이 문제의 핵심이다.
  - `is_queued`로 같은 벽돌을 두 번 큐에 넣지 않아 연쇄가 무한히 돌지 않는다.
  - `board[row][col] = 0`을 **pop 시점**에 하므로, 폭발 범위 `blast_range`는 항상
    원래 숫자를 그대로 읽는다. 큐에 넣을 때 0으로 지웠다면 범위를 잃어버렸을 것이다.
- `apply_gravity`는 칸을 하나씩 내리는 대신, **열마다 남은 벽돌만 순서대로 모아
  바닥부터 다시 채운다**. 한 열을 O(H)에 정리할 수 있다.
- 종료 조건은 "구슬을 다 썼을 때" 하나뿐이다. 벽돌이 모두 깨진 뒤에도 계속 쏘지만,
  빈 열은 `explode`가 곧바로 `return` 하므로 답은 틀어지지 않는다.

### 다시 볼 때 고칠 점
- `count_bricks(board)`가 `board`는 인자로 받으면서 `height`, `width`는 전역을 참조한다.
  값이 같아 지금은 동작하지만, 다른 두 함수처럼 인자로 넘기는 편이 안전하다.
- 남은 벽돌이 0이 되면 더 쏠 필요가 없다. 그 시점에 `answer = 0`으로 확정하고 되돌아오는
  가지치기만 넣어도 실행 시간(920 ms)이 크게 줄어든다.

## 복잡도
- 시간: O(Wᴺ · H·W) — 경우의 수 Wᴺ(최대 20,736)마다 폭발 BFS·중력·카운트가 각각 O(H·W).
- 공간: O(N · H·W) — 재귀 깊이 N만큼 격자 사본이 쌓인다. N ≤ 4로 작다.
